Практическое руководство

Запустите проверку Web-платформы

Используйте эту процедуру после реализации изменения Web-платформы. Одной успешной сборки недостаточно: контракты исходников, браузеры, доступность и сохранённые визуальные эталоны — отдельные части проверки.

Запустите детерминированные проверки без браузера

Nushell · проверки без браузера
cd web
^npm run tokens:check
^npm run typecheck
^npm run test:unit
^npm run build
^npm run check:build

Эти команды проверяют сгенерированные адаптеры дизайн-токенов, TypeScript, архитектурные и контентные контракты, статические результаты, метаданные обнаружения и бюджеты пакетов.

Запустите браузерные проверки и проверки доступности

Nushell · браузерная проверка
^npm run test:browser

Матрица охватывает Chromium для настольных и мобильных устройств, Firefox и WebKit: поведение навигации, целостность маршрутов, отсутствие переполнения, взаимодействие с клавиатуры и блокирующие результаты axe.

На RHEL выполняйте браузерный этап в образе Playwright, соответствующем файлу блокировки. Для текущего Web-пакета это Playwright 1.62.1 и образ mcr.microsoft.com/playwright:v1.62.1-noble, а не исполняемые файлы браузеров, установленные на узле Ubuntu.

Проверьте визуальные эталоны

Nushell · визуальная проверка
^npm run test:visual

Не обновляйте снимки лишь ради успешного CI. Создавайте новые эталоны только для намеренного визуального изменения, просматривайте изображения или артефакт GitHub Actions и сохраняйте проверенный корпус отдельным явным изменением.

Рассматривайте CI как доказательство, а не как всю проверку

Pull Request готов, только когда обязательные проверки прошли на его текущей вершине, ожидаемые визуальные артефакты существуют, устаревшие или отменённые запуски диагностированы, а публичные заявления соответствуют зрелости реализации. Полный контракт описан в правилах проверки и выпуска.
